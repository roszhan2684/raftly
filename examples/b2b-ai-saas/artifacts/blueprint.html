Product

From PRODUCT.md and requirements.yaml.

Problem

Sales managers are expected to coach, but reviewing calls is slow: a manager with eight reps doing 15 calls a week cannot listen to 120 hours of audio. Coaching becomes anecdotal, objections go unnoticed until deals are lost, and competitive shifts surface late. Enterprise conversation-intelligence tools exist but are heavy and priced for large organizations (not verified: competitor positioning and pricing need dated research; see RESEARCH.md #6).

ICP

  • ICP (A-006): B2B sales teams of 10–100 reps without an enterprise conversation-intelligence tool, recording calls on Zoom.
  • Buyer: VP or Head of Sales. Admin: RevOps or a sales manager. Primary user: frontline sales managers. Secondary user: reps.

Positioning

For sales managers at growing B2B teams who need to coach without listening to every call, SalesLens is an AI coaching assistant that surfaces objections, competitor mentions and coaching moments with the exact quote and timestamp. Unlike enterprise conversation-intelligence suites, it is coaching-first, set up in under a day, and priced for mid-market teams.

Differentiation

Coaching workflow first (a queue, not a dashboard), evidence on every insight (verbatim quote + timestamp), time-to-value under one day, privacy controls customers can see (retention, consent attestation, deletion).

Design

From DESIGN.md.

Chosen direction

A as the manager home, B as the call detail view, C as the Trends tab (ADR-009, confidence 70). Validated by EXP-001.

Design direction options

Option A — Coaching queue (recommended)

An inbox-style queue of insights grouped by rep, with filters (type, team) and keyboard triage; detail panel on the right.

| Queue ▾ team: West  type: all        | [quote + 30s audio]          |
| ● Dana  · objection: pricing  0.92   | "Honestly the price is..."   |
| ● Dana  · competitor: Acme    0.97   | context transcript ...        |
| ● Lee   · coaching: no next step     | [accept] [edit] [dismiss]     |
|                                      | note: ______  [share with rep]|

Strengths: maps to the core job; generates quality signals (accept/dismiss). Weaknesses: less overview on landing.

Option B — Call-centric library

A call list → call page with transcript, timeline markers and an insights panel. Strengths: familiar from recording tools. Weaknesses: managers still pick calls to review, which is the work we're removing.

Option C — Team dashboard first

KPIs and trends on landing; drill into calls. Strengths: leader-friendly. Weaknesses: indirect path to action; risks becoming shelfware.

Information architecture

Entities: Organization › Teams › Reps › Calls › Transcript › Insights › Coaching notes. Top-level navigation: Queue (managers' home) · Calls · Trends · Settings (Admins). Reps: My coaching · My calls.

Key screens

SCR-queue — Coaching queue (manager home)
  • Purpose: triage new insights. Primary action: accept/share. Secondary: dismiss, edit category, open the call.
  • Data: rep, insight type/category, confidence, call date, quote preview; the detail panel shows quote, audio snippet, context.
  • States: default · empty ("You're all caught up") · loading (skeleton rows) · error (retry; cached list kept) · success (toast "Shared with Dana").
  • Permissions: Manager (own teams), Admin (all).
  • Desktop: two-pane. Tablet: list → detail push. Mobile: list → full-screen detail.
  • Keyboard: j/k move, Enter open, a accept, d dismiss, e edit, s share, ? help.
  • Accessibility: listbox semantics with an active descendant; audio player with labelled controls; confidence as text.
  • Analytics: insight_actioned{action} (no content).
SCR-call-detail — Call
  • Purpose: full context. Data: metadata, audio player, transcript with speaker labels, timeline markers, insights list.
  • States: processing (step + estimate) · failed (reason + retry) · ready · insights unavailable (retry).
  • Permissions: per visibility rules. Responsive: transcript below the player on mobile.
  • Accessibility: transcript as a list of labelled segments; click-to-seek via buttons.
SCR-upload — Upload

Drag-and-drop + file picker, consent attestation (org policy text), resumable progress, limits explained. Errors explain the format/duration limits.

SCR-rep-feed — My coaching

Shared notes as cards (manager, quote, audio, note, reply). Empty: "No coaching yet…". Read status.

SCR-trends — Trends

Period/team filters, objection categories over time (line), competitor share (bar), per-rep table; every chart has a table alternative and a summary sentence; small-sample warnings.

SCR-org-settings / SCR-audit-log / SCR-integrations / SCR-billing / SCR-signin / SCR-notification-settings

Standard settings patterns; destructive actions require typed confirmation; every list has empty/loading/error states.

Accessibility

WCAG 2.2 AA target; keyboard-first triage; colour never the only signal (confidence and status in text); captions/transcript for all audio.

Architecture

From ARCHITECTURE.md and dependencies.yaml.

System overview

A TypeScript modular monolith (ADR-001): the web process (Next.js UI + API routes) and the worker process (pg-boss consumers) share domain modules. PostgreSQL holds all relational data with row-level-security tenancy (ADR-002) and the job queue (ADR-005). Audio lives in S3-compatible storage under per-tenant prefixes (ADR-004). AI calls go through provider interfaces (ADR-006, ADR-007) gated by an eval harness (ADR-008).

Boundaries

Modules: orgs (identity, memberships, roles), calls (ingestion, storage, consent), transcripts, insights (extraction, reviews, notes), trends (read models), billing, governance (retention, export, deletion, audit), notifications. Rules: modules call each other through exported service functions only; only repositories touch the database; every repository requires an org context; provider SDKs live only in adapters/.

Decisions

Chronological Decision Book. Overrides and superseded decisions stay visible.

  1. ADR-001Modular monolith in TypeScript: Next.js web/API plus a background workerACCEPTEDType-1
    2026-10-24 · architect · RECOMMEND · confidence 82 · reversibility medium
    The simplicity ladder, rung 4 (monolith + worker), satisfies every V1 requirement. Long jobs live in the worker (ADR-005). Boundaries keep a later extraction possible.
  2. ADR-002PostgreSQL with shared-schema tenancy enforced by row-level securityACCEPTEDType-1
    2026-10-24 · data · RECOMMEND · confidence 85 · reversibility low
    Defence in depth: application scoping plus database-enforced policies, so one missed WHERE clause cannot leak data.
  3. ADR-003Auth.js with magic links and Google/Microsoft OIDC; organizations and roles in our databaseACCEPTEDType-1
    2026-10-24 · security · RECOMMEND · confidence 75 · reversibility medium
    Keeps identity, tenancy and authorization in one model with no recurring cost while the product is validated. Option B stays the documented path when SAML/SCIM demand appears.
  4. ADR-004S3-compatible object storage with per-tenant prefixes, encryption and lifecycle retentionACCEPTED
    2026-10-24 · platform · RECOMMEND · confidence 85 · reversibility high
    Standard and portable (low lock-in thanks to the de-facto S3 API). Presigned direct uploads keep large files off the web server.
  5. ADR-005Postgres-backed job queue (pg-boss) instead of Redis or a cloud queueACCEPTED
    2026-10-24 · backend · RECOMMEND · confidence 80 · reversibility high
    One fewer system to run (Constitution 5); enqueueing happens in the same transaction as the call record.
  6. ADR-006Speech-to-text through a provider interface; provider selected by a diarization and WER spikeACCEPTEDType-1
    2026-10-24 · ai-ml · RECOMMEND · confidence 65 · reversibility medium
    Speed to a reliable pipeline matters more than owning a model in V1. The spike turns an unverified choice into evidence.
  7. ADR-007LLM extraction with structured outputs, evidence quotes and versioned prompts behind a provider abstractionACCEPTEDType-1
    2026-10-24 · ai-ml · RECOMMEND · confidence 75 · reversibility medium
    Best quality-to-effort for V1. Evidence quotes make insights verifiable (R-003). Abstraction plus eval gating (ADR-008) make the provider replaceable.
  8. ADR-008Evaluation gating: versioned golden dataset and thresholds block prompt or model changesACCEPTEDType-1
    2026-10-24 · ai-ml · RECOMMEND · confidence 85 · reversibility high
    Turns AI quality into an evidence-gated, regression-tested property, like any other test (Constitution 15).
  9. ADR-009Design direction A: coaching queue as the landing view, call detail as drill-inACCEPTED
    2026-10-24 · design-director · RECOMMEND · confidence 70 · reversibility high
    The primary job is "act on coaching moments without listening to every call". A puts that action first, which also generates the accept/dismiss signal for quality monitoring.
  10. ADR-010Stripe for subscriptions, trials, seats and metered audio hoursACCEPTED
    2026-10-24 · gtm · RECOMMEND · confidence 78 · reversibility medium
    Supports both candidate pricing models without re-architecture; widely documented. Keeping our own usage ledger limits lock-in.
  11. ADR-011Zoom is the only V1 integration; CRM linking deferredACCEPTED
    2026-10-24 · product-director · RECOMMEND · confidence 72 · reversibility high
    Prove the core job with the smallest integration surface. The pilot tells us which integration comes second.
  12. ADR-012Retention defaults and recording-consent attestationACCEPTED
    2026-10-24 · privacy · RECOMMEND · confidence 70 · reversibility medium
    Minimisation and controller support without blocking the core flow. Legal review confirms or adjusts the defaults before launch.
